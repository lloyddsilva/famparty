# FamParty

Bonding games for family, friends and teams. A host runs the show from their phone, a TV only displays it, and everyone else plays on their phone with a room code. No signup, no app, no payments — non-goals **for now**.

**Hard rule: no live model calls. No model API keys at runtime.** Content packs are generated once, offline, human-reviewed, and committed (see Content, below).

## Stack

- Next.js ~16.4.x, React 19, Tailwind v4, JavaScript (no TypeScript mid-event)
- **Vercel + Route Handlers only.** No custom server, no WebSockets. Clients poll state ~1s (500ms during an active question), sending their last `version`; unchanged polls return a tiny response. `Cache-Control: no-store` everywhere.
- **Upstash Redis** (Vercel Marketplace) holds all room state — never module-level variables. Same region for the database and functions.
  - Room JSON at `room:{code}` with a TTL, mutated only through a compare-and-set Lua script on its `version` (retry on conflict).
  - Answers/votes are individual Redis hash fields, so 12 simultaneous submissions can't conflict.
  - Timer expiry: the deadline lives in room state; any poll/action after it advances the phase through the same CAS, so exactly one caller wins. No `setTimeout` for game logic.
- **Neon Postgres in production, PGLite locally, same SQL** (family data, from Nov 2). Family data is written asynchronously at round end only.
- Game logic and scoring are pure functions — `(state, action, now) => state` in `src/lib/engine.js`, scoring in `src/lib/scoring.js` — with unit tests (`npm test`).

## Run locally

```bash
npm install
vercel link          # lloyddsilva account
vercel env pull .env.local   # UPSTASH_REDIS_REST_URL / _TOKEN
npm run dev          # http://localhost:3000
```

- Host phone: `/host` — create a room, run the show (start, pause, skip, kick, lock).
- TV: `/tv` → enter the code (or open `/tv/CODE`). Display-only, requests a wake lock, shows a QR code + room code.
- Phones: `/join` or scan the TV's QR code. Pick a name + avatar, play.

Player counts: games need **3–12 players**. Rooms lock once started, expire when idle, and room codes exclude offensive fragments.

## Deploy

Railway is **not** used; deploy is Vercel under the **lloyddsilva** account only.

- A push may not trigger a deploy: confirm with `vercel ls` that the deployment is Ready, and check the build marker from `/api/health` on the live URL.
- Prove builds from a clean git worktree before submitting.
- Real-device tests must run on a URL phones can open without a Vercel login (no deployment protection on the test URL).
- Never deploy during a live session — acceptance testing happens between games.

## Content (offline, once)

- Packs are generated by committed scripts (`scripts/`, from Nov 3) using **Muse Spark** for text and **Muse Image** for art. The API key comes from an environment variable and is never committed.
- Image art appears only on **pack title cards and Finish It prompt cards** — never promised for players' own statements.
- Every pack ships with `reviewed: false`; a human reviews for family-safety and originality, and **the build fails on any unreviewed pack**.

## Games

- **Emoji Decoder** (live) — guess the phrase from emojis; faster correct answers score more. (Generic name; "Pictionary" is a Mattel trademark.)
- **Spotlight** (Nov 1) — two truths and a lie, with a dedicated writing prep phase and a 30-second talk-first story beat.
- **Remember This?** (Nov 2) — true statements saved under a family link come back; guess who wrote them.
- **Spectrum** (Nov 3) — place yourself between two opposites; predict the majority.
- **Finish It** (stretch, first to be cut) — anonymous fill-in-the-blank, exact-match duplicate detection only.

## Privacy notes

Family pages (Nov 2) use an unguessable hashed token: a member link (play/view) and an owner link (export/delete, typed confirmation). They send `X-Robots-Tag: noindex` via header only (never a `robots.txt` block), `Referrer-Policy: no-referrer`, and load no third-party scripts.
